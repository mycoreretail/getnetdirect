GetNetDirect Portal Permissions - v11

ADMIN / MANAGEMENT
- View every lead
- Assign/reassign sales reps
- Set every lead status
- Only role that can set Complete, Not Serviceable, Cancelled or Void
- Verify employee-reported Signed Up and Install Scheduled leads
- Control referral payout amount/status/date/reference
- Create employee/contractor and referral partner accounts

EMPLOYEE / CONTRACTOR SALES REP
- View only assigned leads
- Call, text and email assigned customers
- Update: Contacted, Follow-Up, Pending Customer, Qualified, Signed Up, Install Scheduled, Not Interested, Unable to Reach
- Enter follow-up date, provider, order/confirmation number, install date and sales notes
- Cannot set Complete, Not Serviceable, Cancelled or Void
- Cannot edit payouts
- Signed Up and Install Scheduled are flagged for Admin verification

REFERRAL PARTNER
- Submit referrals
- View only their attributed referrals
- Track lead status and payout ledger
- Download/copy their referral QR, link and flyers
- Cannot edit lead status, internal notes, assignment or payouts

RECOMMENDED FLOW
New -> Assigned -> Contacted / Follow-Up -> Qualified -> Signed Up -> Install Scheduled -> Admin verifies -> Complete
If the customer declines: Not Interested
If unreachable: Unable to Reach
If service cannot be provided: Admin uses Not Serviceable
If an order later cancels: Admin uses Cancelled
Duplicates/tests/fake/invalid records: Admin uses Void

V11 ADDITIONS
Admin alone can open Reports & Trends, read all activity, review partner applications
and activate/deactivate team/partner access in the shared database.
Employees cannot reopen or alter Admin-finalized Complete, Cancelled, Void or
Not Serviceable leads. Existing assigned sales-progress permissions are preserved.
Admin and the assigned rep can log contact outcomes on open leads. Partners cannot.
An outdated lead editor is rejected instead of silently overwriting newer changes.
Payout Approved/Paid transitions require a verified Complete partner referral and
a positive amount; Paid also requires the paid date and payment reference.
These record-keeping functions do not send actual money or integrate payroll.
